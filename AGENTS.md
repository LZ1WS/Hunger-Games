# AGENTS.md

Local Hunger Games event simulator. Zero-dependency Node.js app: no `npm install`, no build, no lint, no test framework. Run with `node server.js` (or `npm start`), open http://localhost:3000. Port via `PORT` env var.

## Architecture

- `server.js` — HTTP server + REST API. Every mutating endpoint writes the full state to `data/game.json` and **returns the complete state object**. Also serves `GET /api/catalog`, `GET /api/content`, content CRUD (`/api/items`, `/api/events`, `/api/locale/:code`) and `POST /api/settings`.
- `engine.js` — all game logic (tributes, relationships, phases, event resolution, item/inventory handling, settings, i18n). Pure logic, no HTTP/DOM. Loads content from `config/` JSON files at startup (`loadContent`, run automatically on require).
- `config/` — **user-editable content, no code needed**:
  - `items.json` — item catalog (`{id,name,emoji,cat,dmg,heal,feed,weight,dur}`; `name` can be a per-locale object `{en,ru,...}`).
  - `events.json` — event pool (see event schema below; `tpl` can be a per-locale object).
  - `globalEvents.json` — global event pool.
  - `personalities.json` — personalities (`{id,name,weights,default}`; `weights` bias the six daily actions; `default:true` ones can't be deleted).
  - `packs.json` — saved tribute packs (see below).
  - `locales/<code>.json` — translations: `__meta__` (code/name/native) + `ui` (frontend labels) + `names` (stat/prof names) + `engine` (log messages). Flat lookups: `tr(state,key)` merges `ui+names+engine`; frontend `t(key)` same.
- `items.js` / `events.js` — **fallback seed data only**, used when the matching `config/*.json` fails to parse. Don't edit these to change game content — edit the JSON or use the UI.
- `public/` — vanilla JS/HTML/CSS frontend, no framework, no build step. `app.js` renders everything via `t()` i18n lookups.

## Conventions / gotchas

- **Frontend contract**: `app.js` does NOT re-fetch after mutations — it renders the state object returned by each API call. Content CRUD endpoints return the created/updated object, not state; the frontend calls `refreshContent()` afterwards.
- **Editing content**: the "⚙ Game Content" panel (setup phase) has Items / Events / Global Events / Personalities / Languages tabs. Every content object carries an `enabled` flag (persisted in the JSON; default true) — disabled items/events/globals/personalities are excluded from gameplay (event pools via `pickEvent`, global triggers, random loot pools via `activeItems()`, boss pools) and hidden from the content tabs by default. Each tab has an Everything/Enabled/Disabled filter and per-row enable/disable toggles (`POST /api/content/enabled` {type,id,enabled}). **Content packs** (`config/contentPacks.json`, API `/api/contentpacks`): a pack snapshots the current enabled-id set for items/events/globals/personalities; loading it enables exactly the pack's contents and disables everything else. Items and events are also hand-editable JSON in `config/`; `POST /api/content/reload` re-reads the files. Items/events CRUD writes the JSON back automatically.
- **Adding events**: each event has `cat` (gather/scout/build/fight/social/rest/survive/night/start), `phase` (`"day"`/`"night"`/`"start"`/`"any"`), `targets` (`1`=self, `2`=pair, integer `N`=self + N−1 others, `[min,max]`=variable group size), `tpl` with placeholders `{self}`, `{other}` (primary other), `{others}` (all others), `{group}` (self + others, comma-joined), `fxSelf`/`fxOther` (applied to *every* other), `rel` (self→all others) and `relRev` (each other→self), `cond` (`skill`/`stat`/`relSelf` vs primary other), `scale` (stat→skill), `weight`. Optional `loot` (array of item ids granted to self) and `fxProf` (per-category proficiency deltas). `fxSelf`/`fxOther`/`fxBoth` values may be a number **or a range `[min,max]`** (rolled per firing via `rollRange`).
- **Targeting**: any event/sub/addon/replace mini-event may set `target` (`"random"`, or `{excludeSelf, cond}`) to affect a random/particular tribute instead of the actor — `pickTributeByTarget` picks a random alive tribute matching `cond` (all conditions ANDed). `cond` supports `skill`/`stat`/`proficiency` (`{name,min,max}`), `personality`, `gender`, `hasItem` (item id in inventory), `hasCat` (item category present) via `tributeMatches`. If no tribute matches, the event fizzles (no log).
- **Flavour-text variants**: `tpl` may be a plain string, a per-locale object `{en,ru,...}`, or an **array of variants** (each a string or per-locale object); `eventText` picks a random variant per firing. The event editor edits each variant for the active language and stores one element per non-empty textarea (a single variant is stored as a bare string/object, not an array).
- **Outcome texts**: an event may have `outcome` — an ordered list of `{when, tpl}`; `outcomeText` evaluates each `when` (a mini-language condition, e.g. `other.dead`, `self.dead`, `other.health < 30`, `other female`) **after effects are applied** and uses the first match's text (no `when` = fallback; otherwise falls back to `tpl`). Used so flavour matches the result (e.g. a duel's death isn't described as a retreat). Editors have an "Outcome texts" section.
- **Weapon texts**: an event may also have `weaponTpls` — per-category text for `melee`/`ranged`/`explosive`. In a fight the engine captures the acting tribute's weapon (`usedWeapon`) and, if a `weaponTpls[cat]` entry exists, uses it instead of the general `tpl` (fallback to `tpl` when no match). The `{weapon}` placeholder renders the (lowercased) item name and works in outcome texts too. Editors have a "Weapon texts" section.
- **Sub-events**: an event may have `subs` — an array of sub-events, each overriding the parent's resolution (`tpl`, `targets`, `fxSelf`/`fxOther`/`fxBoth`, `rel`/`relRev`, `loot`, `fxProf`, `scale`, `cond`, `weight`). `applyEvent` picks one sub per firing (`pickSubEvent`), adjusts participants to the sub's `targets` (`adjustOthersToTargets`), and merges it over the parent (`cat` is always inherited). Subs cannot change the game phase; if the parent's `phase` is `"any"`, a sub's own `phase` filters when it may fire. The event editor has a dedicated **sub-event editor**: a sub-events list in the main event modal plus a pop-up editor modal (flavour variants, targets, effects, relationships, loot, proficiencies, advanced JSON) — subs are kept in a client-side `subs` array and saved with the event.
- **Group sizing**: `resolveEvent` picks a preferred group size (`rollGroupSize`: 2/3/4 for fight/social, 1–3 at night, 1–3 in the bloodbath) and degrades to smaller sizes if the pool has no matching event. `pickOthers` weights who joins (hostile-first for fights, friendly-first for social/night).
- **Stat keys are silently ignored**: `applyEvent` skips `fx` keys not in a tribute's attributes, and `meetsCond` returns false for unknown skill/stat names. A typo means a silent no-op, not an error.
- Valid attribute keys: `health energy food morale supplies combat survival craft charm stealth` (0–100). Proficiencies: `melee ranged explosive tool medical` (0–100). Relationships are -100..100.
- **Stealth**: a `stealth` attribute exists (like the other skills). `night_theft` (flagged `stealth:"theft"`) runs `applyStealthTheft`: the thief rolls `spotted` (stealth vs the victim's `survival`); if unseen it succeeds quietly, grants loot, and sets `self.hidden` (hidden tributes are far less likely to be targeted in `pickOthers`, and a hidden ambusher deals +80% weapon bonus). If caught, the **victim's personality/combat decides the outcome** — aggressive (`combat ≥ 60` or warrior/paranoid) → a fight with health damage, otherwise a confrontation (morale damage); both heavily damage the relationship in both directions. In the confrontation, the **thief's charm** (charm attribute ×1.5, +0.35 if their personality has a `social` weight boost) flattens the relationship damage toward 0, but each prior catch by that same victim erodes it (−0.3 per catch). Hidden is cleared by loud actions (fight/gather/build/social) and on reset. Logged under cat `theft`.
- **API is phase-guarded**: `/api/example` only loads examples in `setup`; `/api/start` needs ≥2 tributes; `/api/advance` only acts in `day`/`night`.
- **Zero player input during the Games**: the user only sets up tributes. Each living tribute's daily action is **weighted by personality + state** in `pickAction`/`actionWeights` (personality `weights` bias the six actions; low food → gather, low energy → rest, hostile relationships → fight), plus a lightweight **adaptive goal** (`computeGoal`, stored as `t.goal` and shown on the card). Rest/Skip skips the day's scavenge roll. There is no `/api/actions` endpoint.
- **Avatar**: a tribute's `emoji` is a free-text field; an optional `img` (data URL from the file picker) overrides the emoji on the card. `updateTribute` accepts both, and `POST /api/tributes` must pass `img` too (don't drop it). Starting items are editable in the tribute editor (catalog select + add/remove, saved as an id array via `items`); `startGames` snapshots them (deep-cloned) into `t.base.items` so they carry into the game and `reset()` restores the setup loadout. `updateTribute` accepts `items` as an id array or `{id:{qty,dur}}` object.
- **Items are automatic**: in fight events **both sides fight with their weapons** — each combatant's best weapon deals bonus damage (scaled by proficiency, halved when the target also has a weapon that parries), degrading durability (`single` items are consumed, proficiency +1 per use). A weapon may carry `spd` (**strikes per exchange**, default 1): it hits that many times per fight, each strike resolved against the target's parry/armor separately (so armor/parry hard-counter fast weapons), durability costs the same ~12 per exchange regardless of speed (`12/strikes` per strike), `bestWeapon`/`bossReadiness`/boss-hunt damage scale by `dmg × spd` (boss hunt is aggregated — one counter-hit per phase), the hidden ambush +80% applies to the first strike only, and proficiency +1 per strike. A weapon's `dmg` may also be a **range `[min,max]`** — `bestWeapon`/`bossReadiness` rank by the midpoint, fight power rolls once per exchange, the boss hunt rolls once per phase, and armor/parry apply per strike. **Armor** (cat `armor`, `prot` stat) mitigates all health loss via `applyFx` and adds to the fight parry defense, degrading as it absorbs hits. Tools boost gather/build/scout, `loot`/`scavenge`/`sponsorGift` grant items, `autoEat`/`autoTreat` consume provisions/medical during upkeep. `bestItem` skips durability checks for consumables (they have no `dur`). Items can also carry `warm` (cold protection) and `firewood` (cat `fuel`) is consumed for warmth.
- **Map** (`state.map`): `biome` (forest/tundra/desert/jungle/mountains/plains — `BIOMES` adds day-heat, night-cold and gather upkeep modifiers), per-type `scarcity` (0–100 for provisions/supplies/weapons/tools/medical/armor — scales loot + scavenge chances via `scarcityChance`), `weather` toggle (random `WEATHER_POOL` events, cold snaps flagged `cold`), `replenish` toggle (once-per-game `maybeReplenish` event at ~12%/day, clears all scarcity and grants items; `replenished` flag resets on `reset`), and `globalEvents` toggle (see below). Configured via the setup "Map" panel → `POST /api/map`.
- **Global events**: `config/globalEvents.json` (fallback `globalEvents.js`) holds a pool; when `state.map.globalEvents` is on, `maybeTriggerGlobal` picks one by weight each day and rolls its `chance` (one at a time — an active global blocks new ones until it ends). Per-event `maxTriggers` caps how often it can fire per game (blank = unlimited), and game-level `map.globalsMin`/`map.globalsMax` set a floor/cap on total triggers (blank = no limit; below the floor, triggers are forced each eligible day). In **boss_slayer** mode the boss is **guaranteed**: `map.bossMinDay` (default 3, set in the Win Condition panel) is the day by which a boss must have spawned, and `map.bossCount` (default 1, Win Condition panel) is how many bosses must spawn — `maybeTriggerGlobal` force-spawns a boss-capable global each eligible day while the number of spawned boss globals (`triggeredBossCount`, counted via `state.globalsTriggered` for any boss global — forced, scripted or dev) is below `bossCount`, **bypassing** the single-global lock, `globalEvents` off, `globalsMax` and the chance roll (it's the win condition); `state.bossSpawned` tracks the first per game. Each has a `duration` (`full_days`/`days`/`nights` × N, or `endless` = runs until the game ends — `durationRemaining` uses `Infinity`), a start/end `tpl`, and can **replace** a phase (each tribute gets inline `replace.day`/`replace.night` events instead of the normal action loop), **influence** it (`mods.buff`/`mods.nerf` applied to all attribute changes in `applyFx`, `disable` removes events by id or `"cat:…"` in `pickEvent`), and/or **add-on** extra per-tribute events (`addon.day`/`addon.night`). Active globals live in `state.activeGlobals` with per-game counts in `state.globalsTriggered`, decremented per phase in `tickGlobals`. Logged under cat `global`. The content editor has a full Global Events tab (add/edit/delete via `POST/PUT/DELETE /api/globals`) with a nested **mini-event editor** modal for the replace/addon day/night lists (tpl variants, targets, weight, effects, relationships, loot), and the globals/mode filter buttons use `globmode.*` locale keys.
- **Boss / NPC squad globals**: a global event may set `boss` — `{name (string or per-locale), emoji, count (squad size), attributes:{health,morale,combat,stealth,defense}, weapons:[{cat (melee/ranged/explosive), dmg}, …] (or a single `weapon`), retaliate (default true), damageMult, behaviors:[...]}`. Boss weapon `dmg` may be a number or a range `[min,max]` rolled per attack; `spd` (default 1) is the weapon's **strikes per attack** — a fast boss weapon hits each patrol target and each hunting tribute `spd` times per phase, each strike resolved/armor-mitigated separately (armor hard-counters fast boss weapons) but aggregated into one log line, with one damage roll per exchange. `retaliate: false` makes the boss **passive** — it deals no counter-damage when hunted (its only damage is the death `explosion`); patrol/drain/steal are separate `behaviors` and still work. On trigger the boss entity is built into `g.boss` with `health = maxHealth = attributes.health × count` and `weapons` (an array; each attack picks a random weapon from it). Attack power is weapon-driven (`bossPower = combat×0.3 + weapon.dmg×(0.5+combat/200)`, ×1/×1.2/×1.4 for melee/ranged/explosive) and `damageMult` (default 1) scales all damage the boss deals to tributes. Each active phase, `resolveBoss` runs the boss's `behaviors` (**drain** = everyone loses a little food/supplies, **steal** = it plunders a random item from a random tribute, **patrol** = it attacks `remainingCount` distinct tributes per phase — one strike per surviving squad unit, +1 when morale ≥ 70 (enraged), damage scaled by stealth-surprise and morale, capped at the alive healthy tributes) and then a **hunt** with **no randomness**: only tributes whose current goal is `slay_boss` engage. `isBossSlayerCandidate`: bold personalities (warrior/hunter/strategist) qualify from readiness ≥ 20, otherwise combat ≥ 55 with decent morale/health, otherwise overall `bossReadiness` ≥ 45 (a score from combat + best weapon × proficiency, scaled by health/morale/energy state). All `slay_boss` tributes attack **together as a squad** (or solo if one) each phase: each deals `(combat×0.6 + weapon bonus) × mitigation` to the boss's health, where `mitigation = max(0.1, 1 − defense×squadFactor/200)` (squadFactor = 0.5 + 0.5×count, so defense grows with squad size), and takes `bossPower×(0.5+morale/200)` back (scaled by remaining units: 0.75 + 0.25×remainingCount; halved when fighting in a squad), boss morale drops per attacker. When health hits 0 the boss is **slain** (log + a random loot drop to every survivor) and the global ends early (`endGlobal`); the global's `onSlay` script hook fires the instant the boss dies — **before** the Boss Slayer winners are decided (authors get `g.boss.participants` to hit everyone who fought it, so a scripted blast can kill wounded fighters and deny them the win). A boss with `explosion` (editable "Death blast damage") additionally deals that much health damage to every living participant as part of the slay. Otherwise it ends when its duration expires — a boss nobody is ready to fight simply runs out the clock. A tribute killed by a boss dies with `_cause:"boss"` (`deathBoss`). Behaviors/attributes are editable in the Global Event editor's "Boss NPC / Squad" section (mode filter `globmode.boss`); the frontend shows an active boss's health bar in the "Threat" panel. Logged under cat `boss`.
- **Script hooks** (power-user "code editor"): events/subs/addons/mini-events accept a `script` string (run as `onEvent` inside `applyEvent`/`applyAddons`) or `{lang, onEvent, postEvent}` — `onEvent` runs before effects, **`postEvent` runs after** (so it can react to `other.dead`, `self.health < 30`, etc.); global events accept `script: {lang,onStart,onDay,onNight,onDeath,onDamage,onSlay,onEnd}`. Scripts run via `new Function` in a `with(ctx)` sandbox (`runScript`/`scriptCtx`) with helpers: `state, self, other, others, memory, boss(), bossName(), triggerEvent(cat, tributeId?), triggerGlobal(id), log(), grant(), grantLoot(), add(), set(), get(), pickTribute(), matches(), any(), byId(), isAlive(), hasItem(), hasCat(), rand(), choose()`. `onDeath` gets `death.tribute`/`death.killer`; `onDamage` (fired from `applyFx`, weapon-fight damage, and boss-hunt damage via `runDamageHooks`, recursion-capped) gets `damage.target/amount/attacker/cause` and reuses the `victim`/`killer` refs — when `damage.target` has a `maxHealth` field it's the Boss itself being hit (use `boss()`/`bossName()`); boss hits also carry `damage.remainingCount` — the dynamic number of squad units still standing, `Math.ceil(health × count / maxHealth)`, updated on every hit and shown in the Threat panel (`×2/3` style); `onSlay` fires the instant a Boss dies before the Boss Slayer winners are decided (use `g.boss.participants`); `g.memory` persists while the global is active. The `{boss}` mini-log placeholder resolves the active boss's localized name. Script errors are logged as a `script` entry, never fatal. **Killer tracking**: fights record `t._killer` (attacker id) when health hits 0 (also via `applyFx`'s `attacker` param), consumed by `checkDeaths`. A **mini-language** (`lang:"mini"`) compiles to the same helpers (`compileMini`): statements `set <var> to <ref/random/true/false>`, `log "…{self|other|killer|victim|target}…"`, `grant <ref> <items>`, `reward <ref> <items>`, `if <cond>` … `end`/`else`; refs `self,other,others,killer,victim,target,random,randomOther` or memory vars; conditions `is/is not` (incl. `none`), `alive/dead`, `ref.stat <op> n`, gender/personality, `hasItem`, `hasCat`. The default `bounty` global event is written in the mini-language (target via `set target to random`, reward via `reward killer …` on `onDeath`, expiry in `onEnd`).
- **Cold / warmth**: cold damage (biome `nightCold`, `cold`-flagged events like `night_cold`, and cold-snap weather) is reduced by `endureCold` — each tribute's warmth comes from **fuel** (`firewood`, consumed), **flint**, warm clothing (items with `warm` in cat `armor`), a **built shelter** (`flag: "shelter"` on `build_shelter` sets `t.shelter`), and paying the rest in **energy** (6 per cold point; freezing only when energy runs out). Gear makes cold free; bare tributes burn stamina or freeze.
- **i18n**: engine messages/stat names resolve via `tr(state,key)` against `settings.language`. Event/item text is authored content: a plain string shows for all languages; an object `{en,ru,...}` picks per language. Adding `config/locales/xx.json` adds a language. `updateSettings` only accepts languages that exist in `config/locales/`. Item names embedded in log messages are lowercased per-locale via `itemNameLC` (`.toLocaleLowerCase(lang)`).
- **Log reveal**: `settings.logReveal` (`off`/`lines`/`type`) + `settings.revealSpeed` (`slow`/`normal`/`fast`) drive a client-side timer in `app.js` that reveals log lines one-by-one or typewriter-style; the reveal cursor persists across advances (`REVEAL_SPEEDS` maps speed → per-line/per-char ms).
- **Auto-play is client-side**: after `start`, `app.js` runs `setInterval`-driven calls to `/api/advance` (speed selector → interval delay in `SPEEDS`). Pause just clears the timer; manual "Resolve Day/Night", hotkeys `Space`/`D`, and the auto interval all call the same endpoint. Whether auto starts automatically is `settings.autoPlay` (configurable in setup).
- `state.settings` (`sponsorGifts`, `autoPlay`, `showChanges`, `language`, `logReveal`, `revealSpeed`, `devMode`) is persisted; `showChanges`/`logReveal` only affect client-side log rendering (log entries store `text` and `changes` separately).
- **Dev mode**: `settings.devMode` (header checkbox) reveals debug panels in each tab. **Event Log tab**: force any global event (`POST /api/dev/global` {id}) or a random regular event of a category (`POST /api/dev/event` {cat, tributeId?}). **Tributes tab**: live edit of a chosen tribute's attributes/proficiencies/personality (via `PUT /api/tributes/:id`) and inventory (`POST /api/dev/item` {tributeId, itemId, remove?}) — mid-game edits never touch `t.base`, so `reset()` restores the setup snapshot (no leak). **Map tab**: weather toggle/force (`POST /api/dev/weather`) and live scarcity sliders (`POST /api/map`). All `/api/dev/*` endpoints return 403 unless `devMode` is on. Engine helpers: `triggerGlobalEvent`, `triggerEvent`, `forceWeather`, `devGrantItem`.
- **Abilities**: `config/abilities.json` (fallback `abilities.js`) holds passive abilities (`{id, name, enabled, cond, weights, damageDealt, damageTaken, upkeep:{food,energy}, coldResist, scavengeChance, targetWeight, extraAction:{stat,below,max}}`). Each tribute has one `ability` (editable in the tribute editor, `updateTribute` accepts `ability`). `cond` (optional mini-language condition, evaluated via `activeAbility` → `evalMiniCond` with `self` = the tribute) gates the **whole** ability — e.g. `"self.health < 30"`, `"hasItem self knife"`. Hooks in the engine: `weights` bias `actionWeights`; `damageDealt`/`damageTaken` multiply weapon/boss damage (alongside `veteranFactor`); `upkeep` adjusts the daily food/energy cost in `resolveDay`; `coldResist` reduces cold in `endureCold`; `scavengeChance` adds to the daily scavenge roll; `targetWeight` multiplies how often `pickOthersFrom` picks them; `extraAction` grants a second daily action while `attributes[stat] < below` (capped `max`/day). Abilities can also carry a `script` object with per-tribute hooks (`onEvent`/`postEvent` when an event involves the tribute — context includes `event = {id, cat, phase}`; `onDay`/`onNight` each phase; `onDamage` when they take damage; `onDeal` when they deal damage; `onKill` when they kill) — context is `self`, `memory` = `t.abilityMemory` (reset per game), plus `damage`/`death` in the damage/kill hooks. Enabled/disabled + content packs treat abilities like other content (`setContentEnabled("abilities",…)`, pack `abilities` array); CRUD via `/api/abilities`. Full editor in the Game Content "Abilities" tab (id/name/trigger-condition/weights/multipliers/upkeep/cold/scavenge/target/extra-action/script-hooks fields).
- **Statistics / leaderboard**: each tribute has `stats` (`kills, fights, thefts, gathers, scavenges, socials, gifts, damage, experience`), reset per game. `kills` from killer tracking in `checkDeaths`; `fights`/`gathers`/`socials` by event category in `applyEvent`; `thefts` via an event `stat` field (set on `night_theft`/`scout_steal`); `scavenges`/`gifts` in `scavenge`/`sponsorGift`. **Veteran points** (`experience`): gained +1 per fight/boss hunt and +4 per kill; `veteranFactor` (exp×0.01, capped 0.5) scales combat damage dealt (`×1+v`) and reduces damage taken (`×1−0.5v`) in weapon fights and boss hunts — tributes with ≥20 exp get a ⚔ Veteran tag on the card. A "📊 Stats" button toggles the stats panel + leaderboard (sortable); it auto-shows on `finished`.
- **Win conditions**: `state.settings.winMode` (chosen in the setup "Win Condition" panel, API `POST /api/settings`) is one of `hg` (default — last one alive), `survivors` (everyone alive when `settings.endDay` is reached wins; a sole survivor still wins early), `boss_slayer` (the game only ends in a win when **all** Bosses are dead — every tribute who dealt damage to any slain boss (`boss.participants`, accumulated in `state.bossSlayers`) and is alive wins; the game continues while any boss remains, and if the last boss flees at the end of its duration, or everyone dies, it's a loss with no winner), or `hg_plus` (the last **faction** standing wins — tributes with the same `alliance` string win together, solo tributes are each their own faction). Endings go through `finishGame(state, winners)` which sets `state.winners` (array) + `state.winner` (first id, for compat) and logs `win`/`winGroup`/`winNone`; `maybeFinish(state)` is called from `checkDeaths`, at the top of `resolveDay` (survivors end-day + hg_plus faction check), from `resolveBoss` on a boss slay, and from `endGlobal` when a boss flees. Alliances are set per-tribute (`alliance` string, editable in the tribute editor + the "Alliances" list in the win panel, saved in tribute packs) and accepted by `POST /api/tributes`/`PUT /api/tributes/:id`. Dynamic alliances run in **hg_plus** mode, or in **any** mode when `settings.alliances` is on (setup "Win Condition" panel) — so `boss_slayer` games can have tributes bonding while they hunt. In **hg_plus** mode alliances are **dynamic**: after any event that changes relationships, `maybeForgeAlliance` (unallied tributes with mutual rel ≥ 55 bond into a pact at 40% per qualifying encounter — a lone tribute may also **join** an existing alliance) and `maybeBreakAlliance` (an ally whose rel with any member drops to ≤ −30 turns on them and **leaves**) run in `applyEvent`. `refreshAlliances` (called from `checkDeaths` and after the alliance hooks) **renames** generated ("A & B"-style) alliances to match their current living members and **disbands** any alliance down to a single member; in non-`hg_plus` modes it also **disbands the last alliance standing** (when every living tribute shares one alliance) so an ally-pact can't stall the game — they re-solo and can re-bond, and the condition re-disbands if it repeats. Each day `resolveSupport` runs **ally support** (a healthy, generous ally — social-weight personalities like caretaker/charmer/optimist — shares food/supplies/morale with a needy member, scaled by their relationship) and **loner trade** (two unallied tributes with neutral-or-better standing exchange supplies, scaled by personality and relationship); both also transfer a real inventory item via `shareItem` (a shareable item — provisions/medical/tool/fuel — taken from the giver's inventory, or "found" from the active catalog if they have none). Fights in `pickOthersFrom` **exclude the acting tribute's own allies**, while social/night picks weight allies higher. Script authors get `ally(a,b)`/`leaveAlliance(t)` helpers and mini-language `ally <ref> <ref>` / `leave <ref>` statements. Forge/join/break/rename/disband/support/trade are logged under cat `alliance`.
- **Tribute packs**: `config/packs.json` (fallback seeded empty) stores saved tribute setups incl. relationships/items. `POST /api/packs` (save), `POST /api/packs/:name/load` (replace current tributes, setup only), `DELETE /api/packs/:name`, `GET /api/packs`. `POST /api/tributes` accepts `gender`/`personality`/`proficiencies`/`attributes` (don't drop them on new tribute creation).
- `data/game.json` is runtime state the server rewrites on every mutation. Don't hand-edit it; a corrupt file is silently replaced with a fresh state on load (old-schema saves are normalized in `loadState`). It's untracked — treat as generated, and `data/` would be a sensible `.gitignore` entry (none exists yet). Same policy for `config/*.json`: the UI rewrites them, so a bad edit just falls back to `items.js`/`events.js` defaults.

## Verification (no test suite)

Engine correctness is checked with a headless simulation, e.g.:

```
node -e "const e=require('./engine.js');const s=e.newState();e.loadExamples(s);e.startGames(s);let g=0;while(s.phase!=='finished'&&g++<500)e.advance(s);console.log(s.phase,s.day,s.winner,s.log.length)"
```

`loadExamples` seeds 8 tributes with preset relationships. Sim runs finish in ~25 turns on average; guard against infinite loops with a turn cap (existing sims use 500–1000).
